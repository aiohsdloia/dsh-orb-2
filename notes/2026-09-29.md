# 2026-09-29

## Cycle: 修复 image-tools 识图（Open Lab / sculab）

### 症状
`image-tools` 技能的 `scripts/recognize.py` 报
`ERROR: provider 'deepseek' is not configured in opencode.json`，识图不可用。

### 根因（已核实）
- 技能只从 `$XDG_CONFIG_HOME/opencode/opencode.json` 的
  `provider.<id>.options.{baseURL,apiKey}` 取凭据（见 `scripts/_config.py:provider_options`）。
- 该 `opencode.json` **没有 `provider` 块**——app 是**运行时注入** provider
  （`debug.log`: `[provider] applied=deepseek/deepseek-flash providers=[deepseek,opencode]`），
  不落盘，因此技能读不到。
- 凭据实际位置：`$XDG_DATA_HOME/opencode/auth.json` → `deepseek.key`（35 字符）。
- baseURL 来源：`$XDG_CACHE_HOME/opencode/models.json`（models.dev 缓存）→
  `deepseek.api = https://api.deepseek.com`。

### 修复
向 xdg-config 的 `opencode.json` 补入：
```json
"provider": {
  "deepseek": {
    "options": { "baseURL": "https://api.deepseek.com", "apiKey": "<from auth.json>" },
    "models": { "deepseek-flash": {} }
  }
}
```
（先备份为 `opencode.json.bak`；未打印/未落库明文密钥。）

### 验证
`recognize.py describe/ocr` 均成功；`--verbose` 打印
`# read by deepseek/deepseek-flash via https://api.deepseek.com`。
→ **deepseek-flash 具备视觉能力**，可直接读图。

### 注意点 / 后续风险
- app 重启若重写 `opencode.json`，provider 块可能被抹掉；届时重跑同一补丁。
- 建议在「设置 → 模型」里正式配一次 provider 使其持久化（当前 app 不写入该块）。
- 控制台中文乱码是 PowerShell 编码问题，与脚本无关。

### Lesson（候选原则）
- **不要声称模型能力（如"无视觉/纯文本"）而不实测**——本次误判 V4.1 Flash。
- **文件型工具依赖的配置，若 app 改为运行时注入，需显式落盘**：先查该工具读哪个文件、缺什么字段，再从实际凭据源（auth.json / models.json）补齐，而不是假设模型不行。
