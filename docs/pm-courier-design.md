# 主机指挥工作流设计（DSH 中间人 · GPT 项目经理 + GLM 编码员）

> 状态：待审。审完再实现。

## 一、角色与职责

```
        你（主人，最终仲裁）
            ▲ 汇报/请示          │ 指示
            │                    ▼
┌───────────┴─────────────── DSH 中间人 ──────────────────────┐
│  读消息 / 发消息 / 说“继续” / 监督 / 汇报                     │
└──────┬─────────────────────────────────────────┬────────────┘
       │ 任务下发             报告上报           │
       ▼                                       ▼
  ZCode/GLM（编码员）                  ChatGPT/GPT（项目经理）
  接任务→编码→自测→报告              架构→发布工作包→验收→发下一任务
```

- **DSH 中间人** = 本项目核心。用 Computer Use 直接操作两个桌面应用，不写代码、不做架构，只做搬运、监督、请示。
- 交互通道：**本对话（OpenLab）就是控制台**。GPT 的发言先贴到这里给你看，你的指示在对话里回复，DSH 照办。后续可加 QQ 推送通知（复用现有周报推送通道）。

## 二、核心循环（每轮一次）

```
① 读 GLM 报告（ZCode 最后一条消息）
② 自动把报告发给 GPT（不打扰你）
③ GPT 产出发言（下一个任务 / 修改意见）
④ DSH 把 GPT 发言贴给你看 + 附上当前上下文摘要
⑤ 你回复：同意（可能附给 GPT 的指示）或修改要求
⑥ DSH 把你的指示发给 GPT（如需）→ GPT 产出修订后发言
⑦ DSH 把最终任务布置给 GLM（粘贴到 ZCode 输入框发送）
⑧ 监督循环：每 3 分钟查一次 ZCode 状态（“已工作 X 分”/输出变化/报错）
   直到 GLM 产出新报告 → 回到 ①
```

## 三、关键规则（你定的，全部内置）

1. **输出不完全 → 发「继续」**：任一方消息在生成中途停止（界面显示未完成/被打断），DSH 在该方输入框发「继续」，恢复其生成。适用于 GPT 和 GLM 两边。
2. **GLM 报告 → GPT 全自动**：不需要你批准。
3. **GPT 发言 → 先给你看**：绝不自动发往 GLM。
4. **你的指示随行**：你附上的指示由 DSH 连同上下文一起转发（目标方按你确认的规则执行）。
5. **卡死告警**：GPT 出现「使用上限/额度」或双方任一报错、超时，立即在本对话报告并暂停循环。

## 五、实现里程碑

- **M-C1 侦察**：只读确认——两个窗口的正文能否可靠读出（元素树文本/复制按钮）；输入框如何定位。
- **M-C2 搬运验证**：跑一轮完整循环（读 GLM 报告 → 发 GPT → 读 GPT 发言 → 给你看 → 等指示 → 布置 GLM），用当前正在进行的项目做真实验收。
- **M-C3 固化**：把循环规则写成 DSH Web 会话预设（“主机指挥台”），开新会话即可进入中间人模式；文档 + git 提交。
