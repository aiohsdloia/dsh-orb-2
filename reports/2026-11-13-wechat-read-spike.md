# 微信读屏 Spike（只读）

日期：2026-11-13
目标：验证能否在不点击、不发送、不修改的前提下，从微信 PC 端读取置顶群内容。
方法：UIA 控件树 + 窗口截图 + OCR/视觉桥。所有原始截图与识别文本只落在 `butler/data/`（已 gitignore），本报告不含任何聊天内容。

---

## 1. 环境

| 项 | 值 |
|---|---|
| 系统 | Windows 11（本机） |
| 客户端 | Weixin 4.1.15.56（`D:\Weixin\Weixin.exe`） |
| 窗口类 | `Qt51514QWindowIcon` |
| 进程 | `Weixin`（登录后主窗口） |
| 工具 | `butler/wechat-reader/uia-read.ps1` + `image-tools/recognize.py` |

---

## 2. 结果摘要

| 通道 | 结果 | 结论 |
|---|---|---|
| UIA 控件树 | 仅 4 个节点：Window → Pane → MMUIRenderSubWindowHW → TitleBar | **不可用于读消息文本** |
| UIA 文本节点 | 无聊天标题、无消息、无输入框文本 | 只能拿到窗口句柄/几何 |
| PrintWindow | 直接调用得到 223B 黑图；窗口置前后得到 118KB 正常截图 | 需要 `-Foreground` |
| CopyFromScreen | 可用（窗口可见时） | 作为 PrintWindow 的兜底 |
| OCR | 成功识别左侧会话列表、右侧消息区、底部输入区 | **可行**，但需分区/放大 |
| 视觉桥 | deepseek-flash 可读图 | 可用于版面理解，不只是 OCR |

**结论：微信 4.x 是 Qt/MMUI 自绘，UIA 基本不可读；读屏必须走“窗口截图 + OCR/视觉桥”。**

---

## 3. 关键发现

1. **UIA 只暴露 4 个节点**：`mmui::LoginWindow` / `MMUIRenderSubWindowHW`，没有会话列表、消息或输入框的文本节点。不要在这条路上继续投入。
2. **PrintWindow 需要窗口置前**：未置前时输出 223 字节黑图；调用 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow` 后正常（约 118 KB）。
3. **OCR 可读出结构化区域**：左侧会话名/预览、右侧消息气泡、底部“发送”都能识别；小字号和表情会丢，标点/同音字有误差。
4. **隐私风险高**：截图和 OCR 文本包含完整聊天内容。必须本地存放、默认不写报告、不上传；云视觉只在明确授权时使用。
5. **窗口类名不可靠**：登录后 UIA 仍报 `mmui::LoginWindow`，但截图已是主界面。不能用类名判断登录状态。

---

## 3.1 分区裁剪（同日追加）

- 当前窗口约 1104×789；左栏 397×789、右栏 707×789、输入区 1104×118。
- 左栏单独 OCR 明显优于整图：会话名、预览、时间可读。
- 视觉模型可以给出“置顶候选”，但**可靠性不足**（会把普通会话误判为置顶）；不能作为唯一依据。
- 结论：置顶识别需要“图标检测 + 用户确认目标群”，不能只靠 OCR/视觉。
- 在确认目标群之前，**不自动点开任何会话**（点开属于写操作）。

---

## 4. 当前实现

`butler/wechat-reader/uia-read.ps1`：

- `-ProcessName Weixin` 或 `-Title "..."` 定位窗口；
- 递归 dump UIA（深度/节点上限），输出 `uia.json`、`uia.txt`、`summary.txt`；
- 尝试 `PrintWindow`，小于 1KB 自动回退 `CopyFromScreen`；
- `-Foreground` 先恢复并置前窗口；
- `-Redact` 只写截断后的控件名（默认仍建议加）；
- **不包含任何点击/输入/发送代码**。

已在本机验证：

- Weixin 登录后主窗口：UIA 4 节点；截图 118 KB；OCR 成功分区。
- Open Lab 窗口：UIA 20 节点；截图 186 KB；PrintWindow 正常。

---

## 5. 下一步（M1 续）

1. **分区裁剪**：左侧会话列表 / 右侧消息区 / 输入区分别截图并放大 1.5–2×，提高 OCR 准确率。
2. **置顶识别**：优先用视觉模型判断会话列表的置顶标记/排序；不要仅靠 OCR 文本。
3. **按群抽取**：点开置顶群是写操作，先不自动做；由用户保持目标群在前台，或后续加“只读打开”审批。
4. **置信度**：对每条抽取结果给出 OCR 置信度/来源区域；低置信度不进任务列表。
5. **隐私**：原始文件只落 `butler/data/`；报告只写聚合结论；云视觉调用需显式开关。
6. **写操作**：在 M6 之前，任何点击/输入/发送都不做。

---

## 6. 结论

- 微信读屏**可行**，但只能走截图+OCR/视觉，不走 UIA。
- 最大成本不是模型，而是**窗口置前、分区裁剪、滚动与去重**。
- 在自动“点开置顶群”之前，先用“用户把目标群放在前台 + agent 只读当前屏”的半自动模式，风险最低。
